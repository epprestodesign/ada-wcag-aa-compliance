### Problem

1. Every Quasar interactive component ships its own `no-outline` class baked into the framework's render output — confirmed directly in the installed `quasar` package. Nothing in app CSS re-adds a focus indicator, so keyboard focus is invisible app-wide.
2. `index.html:6`: `maximum-scale=1` blocks pinch-to-zoom.
3. No skip-to-content link anywhere (`App.vue` is just `<q-layout><q-page-container><CompanyHeader/><router-view/></q-page-container></q-layout>`).
4. `--q-secondary` defaults to `#8C92A0` (`main.ts:57`) — independently recomputed contrast against white ≈ **3.12:1**, fails 4.5:1. This color is a stubbed whitelabel placeholder (`fetchCustomColors()`), so contrast compliance isn't a one-time fix — it needs a contract for future customer branding.
5. `CompanyHeader.vue` nests a `q-btn`/clickable `q-item` inside an `<a>` at both L103-105 (desktop) and L124-133 (mobile). The same pattern recurs in `ContractedHotelCard.vue` (whole card wrapped in `<a>`, nested close button L103-111, nested `ReserveButton` L241) and `LiveHotelCard.vue` (close button L134-142, `ReserveButton` L193).

### Acceptance Criteria

- [ ] Remove `maximum-scale=1` from `index.html:6`.
- [ ] Add a global `:focus-visible { outline: 2px solid var(--q-primary); outline-offset: 2px; }` rule to `global.css`.
- [ ] Add a skip link (`#main-content` target) to `App.vue`.
- [ ] Darken the default secondary color to `#596070` (≈5.8:1) in `main.ts`, and flag `fetchCustomColors()` as needing a contrast contract before real whitelabel colors go live.
- [ ] Remove the `<a>` wrapper in `CompanyHeader.vue` (both desktop and mobile) — use `q-btn`'s own `:href`/`target` props instead.
- [ ] Remove the `<a>` wrapper in `ContractedHotelCard.vue` and `LiveHotelCard.vue`.
