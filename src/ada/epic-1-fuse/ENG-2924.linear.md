### Problem

1. Every filter group (By Brand, Amenities, Distance, Budget, Star Rating, Room Type) uses a plain `<div class="filter-title">` — zero `<fieldset>`/`<legend>` anywhere in the file.
2. The distance slider, radius input, and max-price input have no accessible name at all (max-price: no label, no placeholder, no aria-label — announces only "edit text").
3. Star rating filter buttons convey selection only via a CSS border class, no `aria-pressed`/`aria-label`.
4. All Google Map marker types are plain `div`s/`img`s with only mouse `click` handlers — no `tabindex`, `role`, keydown handler, or `alt` text.
5. Carousel prev/next buttons have zero `aria-label` in the entire file; the slide `<img>` also has a click handler with no keyboard equivalent.
6. City text contrast fails only in the Live flow's hotel card. The Contracted flow's card instead has its own non-semantic clickable `<div>` (availability toggle) with no `role`/`tabindex`/`aria-expanded`.
7. **Correction**: no "results counter" element exists anywhere in the current code (an earlier draft's claim about one doesn't correspond to real markup). The actual gap is that the loading/no-more-results regions have no `aria-live`/`role="status"`.

### Acceptance Criteria

- [ ] Wrap `HotelSearchFilters.vue` groups in `<fieldset>`/`<legend>`.
- [ ] Add accessible names to the distance slider and both numeric inputs; add `aria-pressed`/`aria-label` to star rating buttons.
- [ ] Make all `MapComponent.vue` marker types keyboard-operable (`tabindex`, `role="button"`, keydown handler) and give marker icons real `alt` text.
- [ ] Add `aria-label` to carousel arrows in `ImageCarousel.vue`.
- [ ] Fix `LiveHotelCard.vue`'s city-text contrast; give `ContractedHotelCard.vue`'s availability toggle proper button semantics; add textual star-rating equivalents to both cards.
- [ ] Add `aria-live="polite"`/`role="status"` to `HotelResultsDesktop.vue`'s loading and no-more-results regions.
