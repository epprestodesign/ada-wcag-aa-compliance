### Problem

1. Event title/date (`HomeView.vue:270-273`, `.big-text`/`.small-text`) render white-on-white against a light or default background image — **directly observed live** on the audited test event, effectively invisible. No permanent scrim exists.
2. Logo alt text is a static `"Event Logo"` regardless of the actual event; ad images use generic `alt="Display Image"`, and their `<a :href="image.redirectURL">` can render with no `href` at all since `redirectURL` is an optional field.
3. Traveler +/- buttons are icon-only `q-btn`s with zero `aria-label` anywhere in the file.
4. Search validation is delegated to three child components. Two (`BookingModeSelect.vue`, `LocationSelect.vue`) are native `q-select`s that get `role="alert"` error text for free from Quasar. The third, `RegistrationSelect.vue` ("Registered Team"), is a custom button+popup whose error text (L403-405) is a bare unassociated `<div>` — **confirmed live**: this field's error never announces to a screen reader while its two siblings' do. No field gets `aria-invalid`, and focus never moves to the first invalid field on submit.
5. **New, found via live testing**: the "Registered Team" popup opens a flat, ungrouped list of 200+ checkboxes with a text filter, no visible/announced selection count, and no landmark/grouping.

### Acceptance Criteria

- [ ] Add a permanent dark scrim behind the hero text in `HomeView.vue` (must not depend on the specific current test image).
- [ ] Use real event/company names for alt text; guard the ad `<a>` so it never renders without an `href`.
- [ ] Add `aria-label`s to all four traveler +/- buttons in `TravelerSelect.vue`.
- [ ] Add `role="alert"`/`aria-describedby` to `RegistrationSelect.vue`'s error text to match its sibling fields; add `aria-invalid` to all three search fields on validation failure; move focus to the first invalid field.
- [ ] Add `aria-live="polite"` and a visible/announced selection count to the "Registered Team" 200+-item popup.
